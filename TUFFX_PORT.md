# TuffX+ client port (ViaBlocks + Below Y0)

Client side for the server plugin <https://github.com/tuffnetwork/tuffXplus>, ported to this 1.14.4 workspace.
Toggle both in the ClickGUI (Right Shift): **ViaBlocks** and **Below Y0**. They take effect on the next server join
(both default to ON; they do nothing on servers without the plugin).

## How it talks to the server
| Channel | Direction | Purpose |
|---|---|---|
| `minecraft:register` | C->S | registers `viablocks:data` and `eagler:below_y0` (Bukkit only delivers messages on registered channels) |
| `eagler:below_y0` | C->S | `int,int,int,ubyte len,"ready2"` handshake |
| `eagler:below_y0` | S->C | `y0_status`, `dimension_change`, `chunk_data`, `block_update`, `lighting_update` |
| `viablocks:handshake` | C->S | enables ViaBlocks for the player |
| `viablocks:data` | S->C | `INIT_PALETTE`, `NEW_PALETTE_ENTRY`, `ADD_CHUNK`, `ADD_SINGLE` |

Code: `net/minecraft/client/mods/tuffx/` (`TuffXNetwork`, `Y0Client`, `ViaBlocksClient`, `LegacyBlocks`, `BlockStateParser`).

## Below Y0 (what changed in the engine)
Vanilla 1.14 hard-codes the world as 16 sections (y 0-255). Now:
* `World.minBuildHeight` (0 normally, -64 while the server says y0 is active) replaces the hard-coded 0.
* `Chunk` keeps 4 extra sections (y -64..-1) + a light array; `getBlockState/getFluidState/setBlockState` and light queries route there.
* `ViewFrustum`/`WorldRenderer`/`ChunkRender` size the render-section grid from `minBuildHeight` (20 instead of 16 rows);
  the renderers are rebuilt once when the server sends `y0_status`.
* `IWorldReader.isAreaLoaded`, the void-kill threshold (`Entity`, minecart) use the lowered bound.
* Y0 blocks arrive as **1.12.2 id/meta**; they are converted with `LegacyBlockTable` (generated from PrismarineJS/minecraft-data `legacy.json`).
Singleplayer is unaffected (`minBuildHeight` stays 0).

## ViaBlocks
ViaVersion substitutes blocks newer than the client. The plugin also sends the real states; the client overrides the
substitutes. Overrides are remembered per chunk and re-applied whenever chunk data is re-sent.
Because 1.14.4 has none of the post-1.14 blocks, `net.minecraft.block.ModernBlocks` registers **158 blocks**
(registered *after* all vanilla blocks so vanilla block-state ids don't move): deepslate family (+ores, stairs/slabs/walls),
tuff family, copper family (waxed = alias of unwaxed), mud, calcite, amethyst/budding, moss, rooted dirt, dripstone block, smooth basalt,
raw metal blocks, tinted glass, bamboo/cherry/mangrove/pale-oak/crimson/warped planks+logs+stairs+slabs, nether 1.16 blocks
(blackstone family, nylium, stems/hyphae, netherite, ancient debris, crying obsidian, shroomlight, ...), target, lodestone, honeycomb.
Assets (blockstates/models/textures) were generated by `gen_modern_blocks.py` from the `InventivetalentDev/minecraft-assets` 1.21.4 mirror
into `desktopRuntime/resources/assets/minecraft`. Re-run it to change the block list.

## Known limitations / not tested at runtime
* **Not run-tested.** I could only compile-check (javac against `src/main/java`; the only errors are the 131 pre-existing platform-layer ones)
  and unit-check the wire parsing. Please test on a TuffX+ server and report crashes.
* Not covered (no model/class yet, keeps ViaVersion's substitute): leaves (azalea/cherry/mangrove), plants & vines (cave vines, dripleaf, glow lichen,
  sculk vein, spore blossom), pointed dripstone, amethyst clusters, candles, sculk family, copper bulbs/doors/trapdoors, honey block, fences/doors of new woods,
  signs/hanging signs, items for the new blocks.
* Block names have no lang entries (they show as `block.minecraft.deepslate`).
* The server's `ADD_SINGLE id 0` means "remove override" but palette index 0 is also a real entry (server quirk); that one block would be mis-read.
* Y0 data for chunks that load later is streamed by the plugin's chunk handler; if a server never sends it, new chunks stay empty below y=0.
* `WorldRenderer.loadRenderers()` runs once on join when y0 turns on (brief hitch).
* Light below y=0 comes straight from the server's per-block light bytes (no client light engine for those sections).

## Texture updates (1.21.4)
Every vanilla block texture that differs between 1.14.4 and 1.21.4 was replaced (48 files): the 1.18 ores (coal, iron, gold, diamond, lapis, redstone, emerald),
nether_bricks, red_nether_bricks, nether_wart_block, spruce_planks, pumpkin_top, pistons, scaffolding, cartography table, smoker, stained glass, cocoa,
redstone torch, end rod and a few more. Netherrack and soul sand are pixel-identical in every version since 1.14.4, so they are unchanged.
`water_overlay` was left alone (tinted). Only same-size, non-animated files were swapped.
